# Maintain Project Verification

Use [task verification](references/project-verification.md#task-verification) to check whether the requested feature, bug fix or refactoring still has the right observations. Repair only missing or conflicting links for actual business/architecture impact; retain relevant semantic reviews and normal/failure connected-flow checks alongside layer tests.

Read [shared verification responsibilities](references/project-verification.md). Start from the requested scope, changed callers, requirements and actual evidence. Reuse setup/current work's investigation; do not repeat a project inventory or rerun valid observations solely for another Skill.

Compare product requirements and current entrypoints with map → active selector → real command → observed outcome. Check added features without connections, removed features still selected, changed contracts without revised guidance, dead commands, missing cross-layer observations and UI guide/token/component drift. Implementation is evidence of ownership, not the authority for the expected result.

When `.harness/project.yaml` exists and mapping/cohort/retention is affected, use available `maintain-agent-harness` and its runtime alongside this product review. Combine shared reads while retaining separate findings and verdicts. Do not call Harness irrelevant merely to avoid a combined maintenance task. A non-Harness project requires no automatic installation; retention deletion is never an incidental product repair.

Audit-only ends with findings and their evidence, without writes, launches or side-effecting tests. Authorized improvement continues through the actual owner repair: code for product defects, adapter/driver for observation errors, map/command/guide for drift, shared component/token for repeated UI inconsistency. Reuse `diagnose` and the relevant UI capability. Read [repair and reuse](references/repair-and-reuse.md) when those paths apply.

Use [workflow obligations](references/workflow-obligations.md) for configured project links and resumable review. Its audit computes omissions and changed consumers without executing tests; Harness maintenance consumes the same calculation. Unconfigured projects can retain read-only investigations in that same task/context without setup.

Consume task-relevant `coverage.gaps` and `ui_systems` from the same audit; retain project remainder separately. Unknown matrix cells do not require six declarations for a small task. Repair affected requirement/check/review connections and shared UI consumer references at their existing owners. A missing guide needs project-specific intent/state/responsive/accessibility writing with the existing UI capability; keep token values in the linked code. Preserve declared UI exceptions and inspect whether their reason still applies. Re-audit the actual shared change to find consumer obligations rather than maintaining a second screen list.

Keep feature additions/changes/removals and their map/guide/active selectors in the same functional change. Confirm removed entrypoints really have no callers; remove only active connections and retain historical runs. Execute repaired commands and the affected flow without lowering requirements, assertions, skips or visual baselines. Preserve both verified work and remaining BLOCKED areas.

Review redundant, implementation-coupled or costly checks by the failure each detects. Consolidate only when the remaining mechanism demonstrably rejects the same defect and permits nearby valid behavior. Without that evidence retain the checks and explain why. Counts and coverage alone do not establish value. Do not create a separate test-pruning framework.

Use the existing workflow CLI's read-only `maintain` action with the current request context returned by `start`/`connect`; inherit `AGENT_WORKFLOW_CONTEXT` or pass `--context`, without rebuilding task paths. Explicit `--history-bundle` paths add measured cost/native error/raw detection links; the action already consumes linked feedback/review runs. Treat `declared_overlap` as a review candidate and measured outcome variation as an investigation input. Record reasoned `check_decisions` in the same semantic review. Consolidation needs old/replacement defect detection and a current nearby normal case; authorized requirement retirement instead needs its reason-specific ownership/criteria/remaining-contract proof and no replacement for the retired rule. See the shared verification reference for fields. Keep unique or unproven detectors.
