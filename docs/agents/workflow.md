# Agent Workflow

Start from repository evidence and `.harness/project.yaml`. Capture the current branch and commit, preserve dirty files, and create a feature branch only when repository policy or the work requires one; never assume a default. Shared instructions, schemas, source-of-truth documents, generated resources, and common test interfaces remain sequential in the main session.

Load ignored `.harness/environment-exceptions.json` once per task when present and refresh after relevant environment changes. Do not retry a `skip_until_manual_reenable` capability; use its fallback and report the unavailable name, intent, reason, disable path, fallback, and remaining unverified scope.

Here, Work Packet is the repository's implementation contract for multiple reviewable boundaries or material risk when persistent coordination or risk management materially helps, or when explicitly requested. Explore unresolved product decisions first; use the Goal contract lifecycle when one of those conditions is met or the user explicitly selects it. Small, clear changes use direct development. Within that workflow, define observable Items that match meaningful review boundaries and keep coupled boundaries together. A valid ordinary contract is authorized by default; the user can veto it without performing approval ceremony. Host Goal tracking is optional. Implement dependency-ready core Items first, record logic impact from diff/direct callers/public behavior, and run exact checks; path mappings are candidates only.

Commit each verified complete functional unit, keeping coupled Items and their required tests/docs/generated resources together. Detailed commit and amendment boundaries live in the [execution policy](../../authoring/references/goal-execution-policy.md).

Low-risk descriptive user deltas become `approved_amendment` and continue immediately. The shortcut cannot erase a veto or change contract controls such as decisions, acceptance criteria, dependencies, and risk declarations. Structural/material revisions use a revised canonical contract and explicit authorization; reuse matching user permission already supplied. A new approval question is needed only for uncovered scope or risk.

Close re-evaluates cumulative Git impact, validates Item evidence, writes `result.json`, and moves complete work to retained state. Update only affected durable truth. `complete` is an optional consistency preflight; neither command executes reported product checks. Reuse still-current execution evidence and report the result in final chat. Re-resolve captured base movement and protection before integration. `main` is protected in this repository; leave a verified branch for human integration and never auto-push.
