# Repository Feature Map

This is the canonical user-function map for **repository/harness** verification. Feature owners update the affected row when behavior or its checks change. Results name a Feature ID, or explain why there is no user-feature impact. Path mappings discover candidates; changed logic, callers, contracts and invariants decide the checks.

All rows have FE and BE/API **not applicable**: this repository distributes Skills and local CLIs, with no product UI or API. Data effects below concern files and processes, not an external product database. Command IDs refer to existing command descriptors or `impact.feature_selectors` in [project configuration](../.harness/project.yaml); that file owns argv. The adapter consumes only the first and last columns of this table. Keep one row per unique Feature ID and comma-separated command IDs in the last column.

| Feature ID | Name | Action | Result and invariant | Domain | Side effects | Command IDs |
| --- | --- | --- | --- | --- | --- | --- |
| skill-install | Install and refresh selected Skills | Install the catalog into a project and update resources | Supported Skills match the source; a complete Harness cohort rejects missing, extra or changed resources before mutation | [Install smoke](../scripts/test-install.ps1), [inventory](architecture/skill-inventory.md), [installed CLI tests](../tests/harness/test_core_first_installed_cli_e2e.py) | Project-local Skill trees and install evidence; existing unselected Skills are not automatically deleted | skill-install |
| native-verification | Inspect a native check with evidence | Select a Feature and check, execute it, inspect the record, or assess that run again | Native failure stays failure; unlinked, wrong-target, skipped, zero-test, unavailable, timeout or stale results cannot PASS | [Capture](../scripts/run_check.py), [repository adapter](../scripts/verify_product.py), [testing](testing.md) | A new evidence JSON file; existing evidence cannot be overwritten; bounded foreground process execution | verification-capture, documentation |
| work-preservation | Preserve user changes and resume work | Capture dirty baseline, deliver scoped work and reopen intact work state | User-owned changes stay outside Item commits; corrupt or conflicting state fails closed; resume does not manufacture completion | [Core runtime](../authoring/scripts/core_harness.py), [execution policy](../authoring/references/goal-execution-policy.md) | Git branches, scoped commits, local work roots and retained records in temporary fixtures | work-preservation |
| design-engine-launch | Obtain and reuse the design engine | Invoke the Windows cmd or Git Bash launcher from separate projects | Fresh downloads require matching SHA-256; failures remain visible; a verified version cache is shared | [cmd launcher](../skills/impeccable/scripts/impeccable.cmd), [shell launcher](../skills/impeccable/scripts/impeccable), [native regression](../tests/distribution/test_impeccable_launcher.py) | Version cache and short-lived download staging files; tests use loopback and temporary caches | impeccable-launcher |

The install-script suite includes fixture/mocked CLI cases. Running it does not establish that an external installer or model behaved correctly. Use the real cached/local Skills CLI with [install smoke](../scripts/test-install.ps1) for temporary install/update tree evidence, and set `HARNESS_SKILLS_ROOT` to that installed cohort when running the installed CLI suite. Windows launcher checks use a compiled local engine fixture and an injected curl failure; they do not prove public release/TLS availability. Agent quality, production application, browser UI and external DB behavior remain outside this map's current evidence.

The adapter's PASS applies only to the selected unittest assertions. Other command IDs in a row require their own run. See [Testing](testing.md) for execution, verdict binding, and evidence limitations.
