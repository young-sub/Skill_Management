# Repository Feature Map

This is the canonical user-function map for **repository/harness** verification. Feature owners update the affected row when behavior or its checks change. Results name a Feature ID, or explain why there is no user-feature impact. Path mappings discover candidates; changed logic, callers, contracts and invariants decide the checks.

All rows have FE and BE/API **not applicable**: this repository distributes Skills and local CLIs, with no product UI or API. Data effects below concern files and processes, not an external product database. Command IDs refer to existing command descriptors or `impact.feature_selectors` in [project configuration](../.harness/project.yaml); that file owns argv. The adapter consumes only the first and last columns of this table. Keep one row per unique Feature ID and comma-separated command IDs in the last column.

The [R0–R4 scope](research/agent-workflow-completion-design.md#review-driven-refinement) has been implemented within the recorded local acceptance boundary. The [post-0.1.45 review](research/agent-workflow-refinement-review.md) records reproduced feedback/retirement gaps and source/runtime-summary limits. That review changes documentation only; its proposed runtime fixes are not implemented by the review. Ordinary and Harness follow-up tasks now share current-map-review reuse, reset task scope decisions, and retain unresolved product/architecture findings independently of stale approval. Repository-wide execution reuse remains conservative. Product-independent Agent trials and package freezing preceded actual Labeler acceptance; current evidence and limitations are in the [implementation results](research/agent-workflow-implementation-results.md).

The install-script suite includes fixture/mocked CLI cases. Running it does not establish that an external installer or model behaved correctly. Use the real cached/local Skills CLI with [install smoke](../scripts/test-install.ps1) for temporary install/update tree evidence, and set `HARNESS_SKILLS_ROOT` to that installed cohort when running the installed CLI suite. Windows launcher checks use a compiled local engine fixture and an injected curl failure; they do not prove public release/TLS availability. The [connected product example](../tests/distribution/fixtures/connected_product/docs/index.md) now has actual Chromium/API/Domain/SQLite evidence through the packaged workflow CLI; its project runner owns lifecycle and business assertions. This bounded example does not prove general Agent quality, installed-host acceptance or production applications/external databases.

The adapter's PASS applies only to the selected unittest assertions. Other command IDs in a row require their own run. See [Testing](testing.md) for execution, verdict binding, and evidence limitations.

Version 0.1.47 fixes the [0.1.46 D1–D3 reproductions](research/agent-workflow-refinement-review.md#post-0146-review) at the existing `feedback-repair` and `workflow-obligations` owners: classification changes cannot refresh approval hashes; applicable criterion/guide connection changes and incomplete legacy bindings require a new decision; hook task gaps exclude out-of-task cells while project totals retain them. `verification-results`/`agent-workflow` task summaries connect exact task/request → Feature source/map/criteria → business/architecture × FE/API/Domain → historical/current reuse → raw observation count/location → next obligations. These are scoped feedback/query corrections, not whole-product PASS. Whole-Git/bundle stale protection remains conservative; UI CONNECTED and declared maintenance overlap remain structural signals, not visual correctness or permission to delete a check.

Version 0.1.48 changes **workflow-obligations**, **verification-results** presentation and **agent-workflow** hook consumption: undeclared active scope yields advisory next actions even after review readiness, while valid native results and reasoned N/A remain intact. Declared gaps retain their blocking behavior. One hook shares its source inventory and identical selected/active task audits, keeps exact references/current reuse/detail pointers when trimming, and remeasures on the next invocation. Different states still assess evidence independently; whole-Git/bundle invalidation is retained. Focused workflow/refinement/hook tests cover these boundaries; packaging is separate from independent product reuse and native host delivery.

The inventory now includes the 19 public Skill entrypoints and the setup/design/execution/amendment/close/retention/distribution CLI families. Machine connections live in `extensions.workflow`; the map owns their meaning. Packaging selectors for UI, review, learning and specialist artifacts establish distribution only, not successful Agent work or external product behavior. Review of hidden flows, visual quality and host enforcement remains separate from file coverage. See the [completion design](research/agent-workflow-completion-design.md) and [implementation results](research/agent-workflow-implementation-results.md) for U1-U7 acceptance and remaining limits. Every enhancement updates its affected Feature and verification connection in the same unit; paths alone do not determine impact or Full.
