# Repository Feature Map

0.1.80 follow-up: `harness-setup` validates the bundled capture scripts in the
existing cohort allowlist. `workflow-obligations` counts final display omissions
separately from uninspected task candidates. `verification-results` shares Git
snapshots inside preparation and preflight separately, retaining the later
freshness check. `native-verification` / `agent-workflow` expose capture
`--lookup` for ordinary final-edit source currentness without a task or rerun;
CURRENT source never substitutes for interpreting the captured check outcome.

`workflow-obligations`: prompt context validates an explicit task before its
audit, or returns bounded candidates with `NOT_AUDITED`. It does not audit other
active work. Task blockers/actions and exact lookup pointers have output priority.
Unconfigured development requests receive existing-guide/caller/test discovery
without setup. `tests.distribution.test_workflow_hook` covers request modes,
budget pressure, ambiguity, UI references and read-only lookup; explicit full
audits remain available.

`verification-results`: assertion checks may explicitly select
`source_scope: registered` after reviewing source/dependency completeness.
Preparation binds registered owners and shared UI sources; related edits,
matching additions and deletions stale affected checks while unrelated edits
remain reusable. Shared check owners bind their union. Existing unscoped checks
keep whole-Git invalidation. `test_verification_execution` exercises actual
execution, final edits, read-only stale lookup and only-affected reexecution.

`agent-workflow`: discovery starts at project criteria and affected code, with
section-level references for remaining needs. Large result lookup starts at
summary and exact failed observations; reusable criteria are not reread merely
because another Skill links them. This changes guidance, not model compliance guarantees.

`plugin-package` includes the optional preview/apply global-guidance installer: managed blocks preserve consumer text, exact backups precede changes, and duplicate apply is a no-op. This is separate from native plugin installation.

`verification-results` includes execution from a single installed Skill without an external capture path; six isolated Skill copies execute real checks and resume completed evidence without rerunning commands.

`plugin-package` also owns the portable package `README.md`: it routes the six
outcomes to packaged Skills/references, is included in the content inventory, and
has no checkout-relative guide dependency. The package regression verifies those
links and its hash alongside execution outside the checkout. This distribution
change does not add new workflow verdicts or establish autonomous model acceptance.

The five host Features below are also registered in `extensions.workflow`, using
their existing shared `host-result` selector. They remain optional protected-host
capabilities, separate from ordinary plugin use. Repository ownership validation
checks declared source roots for unmapped files; it does not run a protected host.

`workflow-obligations` in 0.1.75 reuses a current shared capture for structural prevention when the target Feature was preselected. This removes a label-only rerun while retaining malformed/unrelated consumer rejection, source/evidence freshness and required-check obligations.

`native-verification` now accepts a UTF-8 file as byte-preserving stdin in the existing foreground capture. `agent-workflow` exposes it for Windows Unicode transport; file bytes and invalid-input rejection are exercised through real subprocesses. This prevents shell transcoding on that path, not arbitrary document corruption.

`workflow-obligations` / `agent-workflow` in 0.1.73 omit validated review bodies,
feedback bindings and repeated bundle descriptors from lookup summaries. Large
projects also omit previews, retaining full criterion/cell ID denominators,
current/historical verdicts and exact detail pointers. This is read-only
presentation; required checks and task acceptance are unchanged.

This is the canonical user-function map for **repository/harness** verification. Feature owners update the affected row when behavior or its checks change. Results name a Feature ID, or explain why there is no user-feature impact. Path mappings discover candidates; changed logic, callers, contracts and invariants decide the checks.

All rows have FE and BE/API **not applicable**: this repository distributes Skills and local CLIs, with no product UI or API. Data effects below concern files and processes, not an external product database. Command IDs refer to existing command descriptors or `impact.feature_selectors` in [project configuration](../.harness/project.yaml); that file owns argv. The adapter consumes only the first and last columns of this table. Keep one row per unique Feature ID and comma-separated command IDs in the last column.
