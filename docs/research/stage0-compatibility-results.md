# 0단계: 기준·호환성 정리

2026-10-18. 기준 소스는 clean `main@de2e30a642399b2f366cca514bb0d4066226073e`, 작업 브랜치는 `wp-20261018-stage0-compatibility`다. 기존 `20261018-plugin-readiness` 계약과 project-verification 상태는 별도 미완료 작업으로 보존한다. 이 단위는 지침의 적용 조건을 고치는 하나의 직접 개발 단위이며 새 setup/계약을 만들지 않는다. 1단계 이후 구현이나 모델 비교 평가는 포함하지 않는다.

## 책임 점검과 수정

| 소유자 | 판단과 조치 |
| --- | --- |
| `authoring/global/AGENTS.md` | 권한 재사용, 작업 크기에 따른 절차, 동작에 따른 검증이 이미 명시돼 있다. 수정 필요 없음. 프로젝트 명령·Work Packet 기준·CLI 기록 조건을 전역으로 옮기면 중복되므로 유지한다. 전역 원본과 설치본 모두 변경하지 않았다. |
| `agent-workflow` | 표에서는 직접 작업을 허용하지만 본문은 CLI 사용, 미설정 진단의 `start`, 수리 전 feedback 등록을 무조건 지시했다. 지속 기록이 필요한 작업과 기존 연결 작업에만 적용하고, 작은 수정·일회성 진단은 기존 도구와 결과 보고로 충분함을 명시했다. 명령 예시는 순차 실행 목록이 아니며 조회는 `start`하지 않는다. |
| `repair-and-reuse` | 연결된 feedback의 기록 계약으로 범위를 한정했다. 직접 수리도 실패·원인·소유자·검증은 보존하며, 직접 경로를 선택해서 기존 열린 기록을 버릴 수 없다. |
| `project-verification` | 가이드가 없으면 생성하라는 공통 지시를 승인된 setup/수리에 한정했다. audit-only에서는 누락 보고만 한다. |
| 계약 design/execute/close 및 실행·검증 정책 | 기존 계약에만 적용, 기존 승인 재사용, 조건부 RED, 실제 영향에 따른 Full, 선택적 complete가 이미 명확하다. 유지했다. |
| diagnose, 검증 setup/maintain, workflow-obligations | 작은 진단의 무설정 경로, 범위 제한, 프로젝트 PARTIAL과 현재 작업 분리, 조회 무실행이 이미 있다. 유지했다. 검사 통합의 동일 결함 검출 증명과 변경된 예외의 승인 결속은 필요한 보호이므로 제거하지 않았다. |

변경은 원본 지침 세 파일과 매핑된 생성본·manifest에 한정된다. runtime/API/schema는 변경하지 않았다. Feature는 `agent-workflow`, `feedback-repair`이며 검증은 관련 무실행·증거·권한 회귀와 리소스/패키지 검사를 선택한다. 공통 실행 로직의 교차 영향이 없으므로 Full을 요구하지 않는다.

## 후속 비교에 사용할 고정 과제

아래 합격/실패 기준을 후보 실행 전에 사용한다. 기존 과제를 재사용하며 새 평가기나 runner를 만들지 않는다. 비교 시 위 기준 커밋과 후보 커밋, 과제 입력·제품 소스·평가기 해시, 패키지 해시, OS/런타임/브라우저, 실제 모델 ID·추론 설정, 권한·도움 수준을 별도로 고정한다. 한 요인 외 조건이 다르면 인과 비교로 집계하지 않는다.

| 과제·기존 근거 | 기대 행동 / 실패 판정 | 재사용·도움·측정 |
| --- | --- | --- |
| 작은 수정: 기존 connected-product `docs/index.md` 제목 오탈자 | 해당 문구만 수정·읽기 확인. setup/계약/task 생성, 제품 실행, 다른 파일 훼손은 실패 | 이번 격리 복사 소비는 부모가 과제·스킬을 지정한 도움받은 사례. 수정 파일 수, 생성 상태 수, 제품 명령 수, 개입·재작업을 센다. [기존 작은 API 과제](global-guidance-behavior-results.md)는 동작 변경 확장 과제로 보존한다. |
| 조회: 기존 readiness `workflow.json` 및 연결 실행/완료 재개 회귀 | 기존 상태·raw 바이트 보존, 제품 명령 0회, PARTIAL/STALE와 완료 구분. 새 start, 재실행, 성공 세탁은 실패 | 이번 실제 저장소 조회 및 기존 CLI 회귀 재실행. [0.1.76 native 조회](native-plugin-use-results.md)는 과거 도움받은 호스트 근거로만 재사용. 명령 수·파일 해시·잘못된 완료를 측정한다. |

| 버그 수정: 기존 bool 저장 버그·잘못 연결된 BLOCKED 과제 | 공통 validator 수리, bool 거부와 정상 수량 허용, 실제 API/저장 확인, 배포 권한 보존. 승인 경계 삭제·검사 완화·호출자 누락은 실패 | [A/B4 기존 결과](global-guidance-behavior-results.md)의 14개 독립 검사와 사용자 파일 보존은 역사적 근거. 이번 후보 모델 재실행은 하지 않았다. 기존 raw·평가기·소스·모델 조건 재확인 후만 직접 비교 가능. 결함 누락·정상 차단·개입·재작업·시간·비용 측정. |

공통 우선 지표는 잘못된 완료, 결함 누락, 정상 사용 차단이다. 이어 불필요한 setup/계약/승인 질문/상태 생성, 제품 명령·중복 실행, 사용자 개입·재작업, 시간·토큰·비용을 기록한다. 실패·중단·재시도·스킬 미사용도 분모에서 제거하지 않는다. 이번 모델 사용량·비용과 비교 효율은 unknown이다. 단순 지침 길이나 테스트 수로 효과를 주장하지 않는다.

## 이번 실행 근거와 한계

원본 캡처는 `.work/stage0-20261018/`에 보존한다. 기존 증거를 새 PASS로 집계하지 않는다.

- `regressions.json`: 기존 9개 회귀 통과. fresh hook 무설정·무상태, lookup/resume 무실행·바이트 보존, 연결 실행 1회/완료 재개 재사용, 작은 문서 변경의 제품 실행 불요, 원인 owner/실패/정상 근거, 구조 예방, 기존 승인 범위 보호를 확인했다.
- `connected.json`: required connected-product 2개 통과, skip 없음. 실제 브라우저 정상 경로 및 FE payload 오류 검출을 실행했다. API/Domain만으로는 놓치는 오류를 검출하고 저장/재시작/재조회·서비스 정리를 확인했다.
- `lookup.json`: 실제 기존 readiness 조회의 native exit 2는 PARTIAL/INCOMPLETE를 나타낸다. 실행 실패를 PASS로 바꾸지 않았으며 `test_commands_executed=0`이다. `preserved.json`에 기록한 기존 활성 계약·상태 5파일의 해시는 유지됐다.
- `consumer-report.md`: 생성된 스킬을 읽은 보조 Agent가 격리 제품의 오탈자 한 곳을 수정하고 음수 거부를 소스로 진단했다. 17파일 중 해당 문서만 변경, 사용자 메모 보존, setup/계약/task 생성 0회·제품 명령 0회. 소스 진단은 런타임 PASS로 보고하지 않았다. 부모가 과제·스킬을 지정한 도움받은 실제 소비다.
- `package.json`: 패키지·동기화·배포 회귀 27개 통과. 체크아웃 밖 패키지 실행과 덮어쓰기 거부를 포함한다. `docs.json`: 문서 회귀 4개 통과. 리소스 drift, distribution validation 및 `git diff --check`도 통과했다. 새 로직이나 runtime 수정이 없어 문구를 고정하는 새 테스트는 추가하지 않았다.

0단계의 제한된 완료 기준은 충족했다. 무설정 직접 소비와 조회 무실행을 관찰했고 기존 필수 증거·권한 보호가 유지됐다. 후속 비교용 다섯 과제와 실패 판정은 위 표로 고정했으며, 일반적인 효율 개선은 별도 비교 전까지 미확인이다. 1단계 이후를 시작하지 않는다.

기존 B4 비교와 native 결과는 과제·실패 유형·평가 기준을 재사용할 수 있지만, 새 지침의 효율 향상이나 무도움 발견을 입증하지 않는다. 이번에는 선택 조건의 충돌을 제거하고 제한된 실제 소비·보호 회귀를 확인한다. 전역 지침의 추가 개정, 설치본 변경, 유료 모델 비교, push·배포·protected branch 통합은 수행하지 않는다.
