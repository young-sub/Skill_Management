# 독립 경로 검증 오프라인 반증 (2026-10-26)

[설계 기준](agent-coding-system-direction.md#장치-단위-반증)의 "독립 경로 검증"을 플러그인에 넣기 전에
반증한 기록이다. 방법과 사전 등록 기준은 [suite README](../../evals/path-check-offline/README.md)(커밋 `aab29ce`,
검증자 실행 전)가 소유한다. 코딩 Agent는 실행하지 않았고 검증자만 실행했다.

## 결론

**사전 등록 기준 미달. 두 검증자 모두 오탐 기준(참조 구현 `incomplete` 1건 이하)을 넘지 못했다.** 기준대로 이
장치를 플러그인 기본 경로에 만들지 않고, 이 장치의 유료 OFF/ON 평가도 하지 않는다. 경로 후보 계산(B)도
일반화하지 못했다.

| 검증자 | 부분 구현 검출 | 참조 구현 오탐 | 판정 | 비용·시간 |
| --- | --- | --- | --- | --- |
| Claude (같은 모델, 새 맥락) | 10/10 (필요 8) | 5/12 | 미달 | $17.79, 중앙 134초 |
| Codex (다른 모델 계열) | 6/6 (판정 있는 칸) | 4/6 | 미달 | 비용 미기록, 중앙 170초 |
| 경로 후보 계산 (모델 없음) | 조정에 쓴 `rule-all-paths`에서만 적중 | — | 채택 안 함 | — |

Codex는 22칸 중 10칸이 판정 없이 끝났다(기록상 HTTP 429). 남은 칸은 오탐을 늘릴 수만 있어 판정이 바뀌지 않으므로
다시 실행하지 않았다.

## 관찰

- **검출은 정확했다.** Claude가 부분 구현에서 지목한 경로는 10건 모두 숨긴 검사가 실패한 경로와 같았다(수동
  대조). 예: `a-product-source-stale` → 복원 경로, `rule-all-paths` 부분 구현 → 수정 경로.
- **오탐은 대부분 실제 결함이었다.** 참조 구현을 새로 만들고 숨긴 파일 없이 검증자가 남긴 테스트만 다시 실행하니
  `incomplete` 판정 9건(Claude 5, Codex 4)이 모두 단언 실패로 재현됐다(`run.py replay`). 환경 오류는 0건이다.
  아래 분류는 요청 문구에 대한 필자의 판단이다.

| 분류 | 사례 |
| --- | --- |
| 두 모델이 독립적으로 같은 결함 | `a-import` 구형 스프레드시트에서 옵션 칸이 비면 행이 invalid가 되어 설명 수정이 안 됨; `b-sequence` 백업 복원 후 분류가 4~5단계 |
| 한 모델, 요청이 명시한 동작 | `rule-all-paths` NFKC 정규화가 길이 검사 뒤에 일어나 337자 저장 |
| 요청을 엄격히 읽은 동시성 | `a-import`·`a-update` 같은 버전의 동시 수정이 둘 다 200 |
| 범위 해석이 갈림 | `a-offer` 초기화 뒤 복원 충돌, `b-cross` 기존 21자 단위 상품 복사(소급 여부), `a-update` 가져오기의 행 단위 결과 대 HTTP 400 |

- **두 번째 함의:** v2의 숨긴 검사는 요청 동작을 다 덮지 않는다. 적어도 `a-import`, `b-sequence`,
  `rule-all-paths`의 참조 구현은 요청한 동작을 어기는데도 "검증된 성공"으로 셌다. 따라서 v2의 성공 수(OFF 22/24,
  0.1.89 21/24)는 두 조건 모두의 상한이다. OFF와 ON이 같다는 결론은 바뀌지 않는다.
- **장치로서의 문제:** 검증자는 실제 결함을 찾지만 의도한 범위와 엄격한 해석을 구분하지 못한다. 완료한 작업의
  약 40%(5/12)에 사람이 판정할 지적을 붙이므로 자동 완료 판정이나 결과 카드의 기본 항목으로 쓸 수 없다. 사람이
  고르는 명시 호출 검토는 이미 `multi-agent-review`가 맡는다.

## 실행 기록과 제한

- **항목:** 참조 12, 부분 11. precheck에서 22/23이 유효했다. `a-import` 부분 구현은 probe가 기존 회귀를 깨서
  제외했다(소리 없는 실패가 아님).
- **의존성:** `%TEMP%/claude/eval-deps/labeler` 사본은 package manifest를 잃어 `C:/e/deps/`에 원본
  `node_modules`를 새로 복사해 썼다(원본은 읽기만 했다). 손상된 사본은 그대로 두었다.
- **Codex 1차 실행 무효:** 완료된 11칸 모두 Codex memory(`MEMORY.md`, 이 저장소의 평가 용어 포함)와
  agentic-coding `SKILL.md`를 읽었다. Codex 0.160 `exec`는 plugin별 `-c plugins."<id>".enabled=false`를
  적용하지 않았다(Skill 목록에 그대로 남음). 재실행은 `--disable plugins --disable memories`로 했다.
  이 때문에 ponytail도 꺼졌다(Claude 쪽은 agentic-coding만 껐다). 1차 기록은 `codex-contaminated/`에 따로 남겼다.
  오염 표지에 plugin Skill 경로와 memory 경로를 추가했고, 판정 없이 비정상 종료한 세션은 "complete"가 아니라
  오류로 제외한다.
- **편향:** 부분 패치는 Codex가 작성했다. 경로 후보 계산은 `rule-all-paths`로 조정했다.
- **증거 위치:** 원자료는 `.work/path-check-offline/20261026b/`(`report.json`, `replay.json`, 칸별
  transcript·추가 테스트)에 있고 `.work` 보존 정책에 따라 만료된다.
