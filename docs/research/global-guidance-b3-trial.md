# B3 후속 실험 — 2026-10-18

후속 [B4 개정안과 확인 방법](global-guidance-b4-proposal.md)은 문구의 판단 기준과 실행 경로 발견을 분리해 다룬다. B4의 모델 실험은 아직 수행하지 않았다.

**B3는 실제 확인을 시도했지만 완료하지 못했다. 전역 문구의 추가 개선 효과가 확인되지 않아 운영 적용을 권하지 않는다.** 기존 [B1 제안과 첫 실험](global-guidance-trial.md)은 유지하고, [B3 문구](global-agent-instructions-b3.md)는 실험한 대안으로 보존한다. B1도 일반적인 성능 우위가 입증된 안은 아니다.

## 무엇을 바꿨는가

B1의 12개 원칙과 권한·사용자 변경 보존 기준을 유지하고 세 조항만 수정했다. 검증을 요청한 동작과 위험에 맞추고, 결과가 없을 때 실행 상태와 원인을 먼저 파악하며, 충분한 검증 이후에는 새 변경·실패·미해결 우려가 있을 때만 반복하도록 했다. 구체적인 도구 명령이나 추가 금지 목록은 넣지 않았다.

별도의 부모 평가기는 세 구현 모두 실제 HTTP 요청, 정상·오류 입력, 새 API 조회, SQLite 조회, 프로세스 종료의 15개 관찰을 통과했다. 이는 후보가 스스로 검증을 완료했다는 근거가 아니다. 모든 후보가 기존 CSS와 사용자 메모를 보존했다. 후보 과제 도중 부모 지원은 없었고, 명시적인 SKILL.md 본문 읽기는 없었다.

별도 복사본의 기존 run_project.py는 네이티브 workspace 샌드박스에서도 변경된 /health 응답을 실제로 읽었다. 전체 실행은 이후 Chromium spawn EPERM으로 BLOCKED였다. 따라서 HTTP 관찰 자체의 불가능은 입증되지 않았다. 후보의 복합 명령이 정책 차단된 정확한 규칙은 제공되지 않았으며, 서버 실행 일반이 금지됐다고 확대 해석할 수 없다. 부모 확인은 후보의 도구 정책 판정과 동일한 실험이 아니다.

## 비교의 유효 범위와 비용

실행 전 동일 seed·사용자 변경 해시를 확인했다. A 재시도와 최초 B3는 cwd·전역 본문·CR 줄바꿈만 정규화하면 실제 user/developer 메시지가 동일했다. 테스트 홈의 agentic-coding 0.1.75 및 실제 안내에 포함된 39개 스킬 조건에서 수행했다. 운영 홈의 0.1.76·Ponytail 조합을 검증한 것은 아니다.

B3 반복에서는 런타임이 pages/work-pets 등의 추가 스킬을 노출해 안내 목록이 48개로 늘었다. 초기 통제 비교에는 없던 목록이므로 이 실행은 보조 관찰로만 남긴다. 설정이나 설치 스킬을 수동으로 바꾸지 않았고, 실제 메시지 차이를 별도 diff로 보존했다. 최초 네트워크 실패 세션에는 workflow hook 추가 문맥도 있어 행동 비교에서 분리했다. B3의 CRLF가 로더에서 CRCRLF로 전달되어 기존 문자열 검사는 false였지만, CR 제거 후 전역 문구 내용 일치를 확인했다. 원시 출력은 고치지 않았다.

승인한 최대 4세션을 모두 사용했다. 모델 응답이 있었던 3세션 합계는 51.7초, 보고된 입력 320,348(캐시 276,352), 출력 2,788이며 reasoning 236은 출력에 포함된다. 네트워크 실패까지 실행 시간은 65.9초다. 최초 실패의 사용량과 실제 금액은 unknown이다. 후속 실행 한도에는 그 실패를 입력 200,000·출력 4,000으로 보수적으로 예약하여 계산했다. 이는 실제 사용량 추정치가 아니다. 준비 전체 시간은 unknown이다.

준비 오류도 보존했다. 실행 전 한도 상수 치환 오류를 바로잡았고, B3 버전명을 condition에 넣어 실행기 검증에서 거부된 건은 모델 세션 시작 전 B로 수정했다. 네트워크 재시도는 승인된 호스트 접근으로 수행했으며 후보의 workspace-write·approval never 조건은 유지했다. 테스트 홈 전역은 실행별로 회수하고 설정을 복구했으며, 저장소 원본과 두 운영 전역 경로의 해시가 그대로임을 확인했다.

## 판단과 다음 행동

이번 결과는 B3가 A보다 실제 관찰을 더 시도했다는 제한된 관찰을 제공하지만, 완료·비용 개선은 입증하지 못한다. B3 추가 문구를 채택할 실험 근거가 부족하므로 B1 검토본과 운영 적용 보류를 유지한다. 전역 문구를 더 강화하는 실험은 여기서 종료한다.

다음에 확인할 대상은 도구·스킬 운영 계층이다. 복합 명령의 정책 차단 원인을 분리하고, 기존 서비스 시작·준비 확인·오류 수집·결과 회수 기능을 필요한 범위에서 재사용할 수 있는지 확인한다. 모델 실험 재개 시에는 실제 제공되는 스킬 목록을 고정한 뒤, 정상 실행 조건과 장애 조건을 분리해야 한다. 새로운 일반 실행 프레임워크나 전역 금지 조항 추가는 현재 근거로 정당화되지 않는다. 해당 정비나 추가 모델 실행은 이번에 수행하지 않았다.

원시 자료는 `.work/global-guidance-b3-20261018/`에 보존한다: `candidates/` 원문·B3·diff, `run-ledger.json`, `budget-final.json`, `condition-comparison.json`, `results/` 세션·명령·diff·프로젝트 스냅샷·독립 평가, `preparation/` 준비 오류·환경 확인·문맥 차이. 이 문서와 B3 대안만 추가한 documentation 변경이며 실행 Feature·운영 원본·설치본은 개정하지 않았다.
