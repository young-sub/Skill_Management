## 규칙

- 제품 코드(테스트가 아닌 파일)는 수정하지 마세요. 확인용 테스트는 새 파일로만 추가하세요.
- 의존성을 설치하거나 갱신하지 마세요. 이미 있는 `node_modules`를 쓰세요.
- 기대 동작은 요청에서 도출하세요. 구현을 실행해서 기대값을 정하지 마세요.
- 사용자가 실제로 쓰는 진입점(API 처리, 공개 함수, 화면 동작)을 기준으로 확인하세요.
- `incomplete`는 요청 위반을 보여 주는 실패 테스트를 직접 작성해 실행했을 때만 판정하세요.

마지막 줄에 아래 형식의 JSON 한 줄만 출력하세요.

{"verdict": "complete" 또는 "incomplete", "violations": [{"path": "위반 경로", "test": "파일:줄", "observed": "관찰한 결과"}]}
